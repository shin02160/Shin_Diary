# My Little Universe — 22~27단계

Next.js / TypeScript로 만든 개인 경험 아카이브입니다. 원본 요구사항 문서 두 개는 변경하지 않았습니다.

## 실행

```powershell
cd D:\Shin\Diary
npm install
npm run dev
```

브라우저에서 터미널에 표시된 주소(기본 http://localhost:3000)를 엽니다.

## 구현 기능

- 홈, Memories, Continue, Collection, 달력, 활동 상세, 설정
- 본문 한 줄만으로 기록 저장. 제목·활동 연결·감정·장소·태그는 선택사항
- 기록 초안을 현재 탭의 sessionStorage에 보관하고 새로고침·화면 복귀 시 복원
- 활동 생성·편집, 관심 있음 / 경험 중 / 잠시 보관 / 만족 완료 전환
- 마지막 진행·다음 행동·재개 메모·참고 링크·만족 메모와 최근 중단 날짜
- 활동 상태와 독립적인 아카이브 및 보관함 보기
- 홈·타임라인·활동 상세·달력에서 동일한 기록 표시
- localStorage 저장, 여러 탭 변경 반영, Web Locks를 통한 동시 저장 직렬화
- 활동 편집 충돌 감지, 저장 실패 시 입력 유지 및 재시도, 손상 데이터 덮어쓰기 차단
- 샘플 라벨·샘플 표시 필터, 설정의 원본 JSON 백업
- 반응형 화면, 검색·카테고리 필터, 달력 월 이동·날짜 선택

## 저장 범위와 제약

브라우저는 로컬 입력 대기·조회 사본을 보관합니다. 같은 주소(프로토콜·호스트·포트)와 브라우저에서만 기록이 유지됩니다. localhost와 127.0.0.1, 서로 다른 포트는 저장소가 다릅니다. 사이트 데이터 삭제 시 사라지므로 중요한 기록은 설정에서 백업하세요. 백업 JSON은 설정의 **백업에서 복원**으로 병합할 수 있습니다. 탭을 닫으면 미저장 초안은 사라질 수 있습니다.

안전한 동시 저장을 위해 Web Locks와 HTTPS 또는 localhost 환경이 필요합니다. 기능이 없으면 저장을 차단하고 안내합니다. localStorage 및 sessionStorage는 암호화된 원격 저장소가 아닙니다.

기존 샘플은 사용자 기록과 라벨로 구분됩니다. 샘플 활동을 수정·저장하면 해당 활동은 사용자 활동으로 취급합니다. 달력에서는 샘플 일정과 직접 열어본 ICS 일정을 라벨로 구분합니다.

브라우저 저장 활동은 서버에서 조회할 수 없으므로 활동 URL은 서버 라우트가 열린 뒤 클라이언트에서 존재 여부를 확인합니다. 다른 브라우저에서 사용자 활동 URL을 열면 찾을 수 없다는 안내가 표시됩니다.

3단계에서 Notion 서버 API·앱 비밀번호 로그인·수동 저장/불러오기·충돌 선택·미반영 상태를 구현했습니다. 실제 토큰과 앱 전용 두 데이터 소스 설정이 필요하며, 준비 방법은 [NOTION_SETUP.md](NOTION_SETUP.md)를 참고하세요. 설정 전에는 브라우저 저장을 유지합니다. 4단계에서 네이버 ICS 파일의 읽기 전용 미리보기, 반복·시간대 처리와 비교를 구현했습니다. 파일을 서버에 전송하지 않으며 새로고침하면 가져온 일정은 사라집니다. [ICS 사용 안내](CALENDAR_IMPORT.md)를 참고하세요. 5단계는 별도의 Calendar Events 데이터 소스에 일정 저장 및 조회를 지원합니다. 설정과 사용 방법은 [ICS 사용 안내](CALENDAR_IMPORT.md)를 참고하세요.

## 검증

```powershell
npm test
npm run lint
npm run build
npm run typecheck
```

전역 `playwright-cli`를 사용한 브라우저 검증:

```powershell
npm run start -- --port 3102 --hostname 127.0.0.1
# 별도 터미널: 반드시 별도 테스트 세션 사용
playwright-cli -s=diary-test open http://127.0.0.1:3102
playwright-cli -s=diary-test run-code --filename=scripts/verify-step2.js
playwright-cli -s=diary-test close
```

`verify-step2.js`는 실행한 Playwright 테스트 세션의 앱 저장소와 초안을 초기화한 뒤 테스트 데이터를 생성합니다. 개인 브라우저에 연결해 실행하지 마세요. 캡처는 `artifacts/`에 저장됩니다. 기존 샘플 탐색 회귀 스크립트는 `scripts/verify-ui.js`이며 별도의 깨끗한 세션을 사용합니다.

2026-11-11 2단계 검증: lint·production build·typecheck 통과. Chromium에서 53개 확인 항목 통과(실제 저장·초안·활동 연결·상태 전환·보관·동시 저장·편집 충돌·저장 실패 재시도·손상 데이터 보호·안전한 텍스트 표시·백업·4개 화면 폭 확인 포함). 확인 항목 수는 독립적인 테스트 케이스 수가 아닙니다.

기존 탐색 화면 회귀 검증도 171개 확인 항목이 통과했습니다(360~1440px의 7개 폭). 실행 중인 개발 서버의 http://localhost:3000에서도 홈 표시를 확인했습니다.

3단계 API 테스트는 `npm test`, Notion 설정 UI 검증은 `scripts/verify-step3.js`를 사용합니다. 이 검증은 모의 API와 별도의 Playwright 세션을 사용하며, 해당 테스트 세션의 브라우저 앱 저장소를 초기화합니다. 실제 Notion 연결은 설정 후 별도 확인이 필요합니다.

2026-11-11 3단계 최종 검증: 서버 단위/통합 테스트 18개 통과, 실제 Next HTTP 라우트 확인 13항목 통과, Notion 설정 브라우저 검증 24항목 및 기존 기록 흐름 53항목 통과. lint·production build·typecheck 통과. 확인 항목 수는 독립적인 테스트 케이스 수가 아닙니다.

실제 HTTP 라우트 검증은 빌드 후 `npm run test:http`로 실행합니다. 가짜 자격증명을 별도 3104 포트 서버 프로세스에만 전달하며 Notion 네트워크 요청을 하지 않습니다. 생성한 임시 저널 파일만 정리합니다. Notion UI 테스트 스크립트 실행 방법은 기존 Playwright 명령의 파일명만 `scripts/verify-step3.js`로 바꿉니다.

6단계에서 달력 일정으로 기록을 작성하고 기록에서 당시 일정 정보와 날짜를 확인할 수 있습니다. [일정에서 기록 작성](CALENDAR_IMPORT.md#일정에서-기록-작성)

7단계에서 새 ICS 파일의 캘린더와 기간을 기준으로 신규·변경·동일 일정과 누락 후보를 검토할 수 있습니다. [다시 가져오기 안내](CALENDAR_IMPORT.md#같은-캘린더-다시-가져오기)

8단계는 테스트 계정용 네이버 CalDAV 읽기 검증 도구입니다. [실행 안내](CALDAV_PROBE.md)

9단계에서 추억 화면의 검색어와 카테고리에 날짜·장소·태그·연결 활동 필터를 조합할 수 있습니다. 날짜는 기록에 표시된 날짜를 기준으로 비교합니다.

10단계에서 본문이나 관련 링크로 기록을 남길 수 있습니다. 추억 카드의 **관련 링크**를 펼치면 사이트와 주소가 표시됩니다. Notion에 링크를 반영하려면 Entries에 Source Links 텍스트 속성을 추가하세요.

11단계에서 추억의 **월별 회고 보기**로 월별 기록 수와 기록한 날, 카테고리와 연결 활동, 해당 월의 기록을 확인할 수 있습니다.

12단계에서 JSON 백업의 활동과 기록을 미리 보고 현재 브라우저에 병합할 수 있습니다. 같은 ID의 내 항목은 현재 내용이 우선하며, 샘플은 백업의 내 내용으로 복원됩니다.

13단계에서 설정의 **내 기록 Markdown으로 내보내기**로 내 기록과 활동을 한 파일에 내려받을 수 있습니다. Markdown은 열람용이며 복원은 Diary JSON 백업을 사용합니다.

14단계에서 추억 카드의 **기록 편집**을 열어 본문·날짜·링크·분류를 수정할 수 있습니다. 수정한 기록은 설정에서 Notion에 반영할 수 있습니다.

15단계에서 활동 상세의 **활동 회고 보기** 또는 월별 회고의 **회고 보기**로 연결된 기록을 오래된 날짜부터 볼 수 있습니다. 기록 기간, 기록한 날, 기록에 남긴 장소도 함께 표시합니다.

16단계에서 추억 화면의 **추억 다시 보기**로 이전 해 같은 날짜의 내 기록을 모아보거나, 오늘보다 앞선 내 기록 중 하나를 무작위로 볼 수 있습니다.

17단계에서 컬렉션의 **카테고리별 갤러리**로 활동을 카테고리별로 둘러볼 수 있습니다. **관심사 태그**는 검색어, 카테고리, 샘플 및 아카이브 설정과 함께 적용할 수 있습니다.

18단계에서 **이어서 하기**의 재개 카드에 마지막 진행, 중단한 날, 다음에 할 일, 재개 메모, 참고 링크, 최근 연결 기록 최대 3개를 표시합니다.

19단계에서 설정의 **기록 리마인더**를 켤 수 있습니다. 기본값은 꺼짐이며, 켜면 오늘 날짜의 내 기록이 없는 날 홈에 안내가 표시됩니다. **오늘은 닫기**는 같은 브라우저에서 그날 안내를 숨깁니다.

20단계에서 **이어서 하기 → 아카이브 활동**에서 보관한 활동을 찾을 수 있습니다. 내 활동의 **활동 재개**를 누르면 아카이브에서 나와 경험 중으로 바뀌며 기존 재개 메모와 연결 기록을 그대로 볼 수 있습니다.

21단계에서 기록 폼의 **본문에서 링크·태그 채우기**를 누르면 본문에서 HTTP(S) 주소와 해시태그를 찾아 관련 링크와 태그 칸에 추가합니다. 브라우저에서 처리하며 본문은 그대로 두고 추가된 항목은 저장 전에 수정할 수 있습니다.

22단계에서 기록당 사진 한 장을 첨부할 수 있습니다. 15MB 이하 JPEG·PNG·WebP 파일을 브라우저에서 축소해 JPEG로 저장하며 Diary JSON 백업에 포함합니다. Notion에서 사진을 함께 저장하려면 Entries에 Diary Photo 텍스트 속성을 추가하세요.

23단계에서 관련 링크의 **링크 미리보기**를 누르면 공개 HTTPS 페이지의 제목·설명·대표 이미지를 가져옵니다. 사이트가 제공하는 정보와 응답에 따라 일부 항목만 표시될 수 있습니다.

24~25단계에서 컬렉션의 **목록 보기**, 달력의 **외부 일정 출처**와 일상 필터를 추가했습니다. 외부 일정의 카테고리는 연결된 기록을 기준으로 표시합니다. 설정의 최근 Notion 반영은 해당 브라우저에서 확인된 저장 결과를 표시합니다.

26단계에서 예약·지출·영수증 링크를 기록에 추가할 수 있습니다. Travel Hub에서 직접 선택하려면 .env.local에 .env.example의 네 가지 Travel Hub 데이터 소스 ID를 설정하고 Diary 통합에 조회 권한을 부여하세요. Notion에도 연결을 저장하려면 Entries에 Travel References 텍스트 속성을 추가하세요.

27단계에서 본문 첫 줄을 제목으로 가져오기, 재개·월별 회고 초안, 중복 본문 후보 확인을 추가했습니다. 이 기능은 브라우저 안에서 처리합니다.
