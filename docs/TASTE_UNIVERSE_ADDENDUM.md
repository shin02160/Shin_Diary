# Taste Universe 기획 보완

`My_Pastel_Diary_Taste_Universe_Improvement_Plan.md`(v1.0)에 빠져 있던 결정을 정리하고 구현 상태를 기록한다.

## 1. 추출 방법

| 단 | 방식 | 결과 | 근거 등급 | 상태 |
| --- | --- | --- | --- | --- |
| A | 규칙 | “좋았다”, “인상적이었다” 등 끌림을 직접 적은 문장을 원문 그대로 인용 | 사실 | 구현 |
| B | AI (직접 실행) | 문장별 특성 제안과 근거, 기록 간 연결 가설 | 해석·가설 | 구현, AI 키 설정 필요 |
| C | 직접 편집 | 문장에 특성 붙이기, 맞아요/아니에요 | 확정 | 구현 |

- A단은 끌림 표현이 없는 문장을 싣지 않는다. 감정이나 이유를 만들지 않는다.
- “좋지 않았다”, “별로였다”처럼 뒤집힌 표현은 제외한다.
- 월간 회고는 월 정밀도로 다루고, GPT가 만든 회고는 제외한다.
- B단은 버튼을 눌렀을 때만 실행되며 A단이 뽑은 문장과 제목·날짜·영역만 한 번에 80개까지 전송한다. 일기 전문은 보내지 않는다.
- AI는 문장 번호로만 답한다. 보낸 번호가 아닌 응답은 버리므로 인용문을 지어낼 수 없다. 특성은 2~12자, 문장당 3개까지 받는다.
- 연결 가설은 서로 다른 기록 2건 이상에 같은 특성이 제안됐을 때만 받는다.
- 제안과 가설은 사용자가 받아들이기 전에는 확인한 취향으로 세지 않는다. 지운 제안과 아니라고 한 가설은 다시 보이지 않는다.
- 서버 설정: `OPENAI_API_KEY`, `OPENAI_TASTE_MODEL`(없으면 `OPENAI_REVIEW_MODEL`).

## 2. 검토 결과 저장

- 1차는 브라우저 저장(`mlu.taste.reviews`)이며 JSON 파일로 내보내고 가져올 수 있다. Notion은 바뀌지 않는다.
- 관찰의 식별자는 “원본 페이지 ID + 인용문”으로 만든다. 다시 읽어도 같은 문장은 같은 식별자를 갖고, 아니라고 한 문장은 다시 나오지 않는다.
- 여러 기기에서 공유하려면 Notion에 “취향 노트” DB를 신설한다. 원본 DB는 건드리지 않는다. 별도 승인 사항이다.

## 3. 본문 읽기

- 기록 본문은 페이지 ID와 Notion 최종 수정 시각으로 캐시한다. 수정된 기록만 다시 읽는다.
- 한 번에 2건씩 읽고, Notion이 요청을 제한하면 멈춘 뒤 다시 읽기 버튼을 보여준다.
- 캐시에는 인용한 문장만 저장하고 본문 전체는 저장하지 않는다.
- 본문을 읽기 전에는 요약(Content)에서 찾은 문장을 먼저 보여준다.

## 4. 날짜 정밀도

- 관찰에 `day` 또는 `month` 정밀도를 둔다. 월 단위는 “2026년 10월”로만 표시한다.
- 현재는 제목의 “YYYY년 M월” 표기로 월 단위를 판단한다.
- Notion `Date Kind`에 `month` 옵션을 추가하면 명시적으로 지정할 수 있다. 별도 승인 사항이다.

## 5. 그 밖의 규칙

- 특성 어휘: 기본 제안 목록에서 고르거나 직접 입력한다. 이미 쓴 특성이 먼저 제안된다.
- 원문 수정: 확인해 둔 문장이 원문에서 사라지면 지우지 않고 “다시 확인이 필요한 항목”으로 보여준다.
- 검토 부담: 확인하지 않은 문장도 그대로 보여주며 확인을 강제하지 않는다.
- 새로운 발견 후보: 경험 유형까지만 제안하고 구체적인 행사·장소명은 만들지 않는다. 미구현.
- 빈도 기반 시기 흐름은 “기록으로 본 활동 흐름” 아래 접힌 보조 자료로 둔다.
