# v2 데이터 계약

| Notion 원본 | 읽기 API | 앱의 소비 경로 |
| --- | --- | --- |
| Entries | wiki-entries, wiki-entries/[pageId], archive | Wiki 전문·사진, 탐색·홈·관심사·연대기 카탈로그 |
| Activities | archive | 이어서 하기 및 공통 카탈로그 |
| Calendar Events | life-calendar | 캘린더, 탐색, 관심사, 리포트 |
| 관심사 아카이브 | interests | 주제와 연결 근거 |
| 타임라인 이벤트 | timeline-events | 연대기 원본 |
| 여행·공연 DB | collections, collections/detail | 대표 카드와 상세 |

경험일과 시각 내림차순, 수정 시각, 원본 키 순서로 정렬한다. 기간형 자료는 시작일 기준으로 정렬하고 종료일까지 표시한다. 캘린더의 종일 종료는 배타적 경계를 사용한다. 날짜 미상 구역은 카탈로그에 전달된 자료를 대상으로 하며 현재 Wiki Entries API가 날짜가 비어 있는 페이지를 건너뛰는 것은 남은 격차다.

Notion 페이지 ID와 캘린더 Import Key를 이용해 동일 소스 내 중복을 제거한다. 일정과 후기의 동일 발생 건은 기존 명시적 연결을 이용한다. 서로 다른 원본이 같은 경험인지 명시적 근거가 없으면 각각 남긴다. 달력이 경과한 상태와 실제 참여는 별도 필드다. 확인된 필라테스는 기존 사용자 확인 규칙을 재사용한다.

관심사 연결에는 명시적 관계, 브라우저 승인, 제목·태그·요약 등 추천 근거가 있다. 연대기에는 날짜가 있는 비일정 기록의 Notion 관계 및 추천 근거를 표시한다. 추측으로 감정이나 선호 강도를 만들지 않는다. Notion 쓰기는 이 개편에 포함하지 않는다.

관심사의 다른 표기는 관심사 DB의 `별칭` 속성(다중 선택 또는 쉼표·줄바꿈으로 구분한 텍스트)에서 읽는다. 앱은 관심사 이름, 이름에서 문장부호를 뺀 표기, 별칭만으로 기록 제목·태그·본문을 찾으며 코드에 고정된 별칭은 없다. 속성이 없으면 이름 표기와 일치하는 기록만 추천된다.
